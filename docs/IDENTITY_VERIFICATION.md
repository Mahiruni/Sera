# SERA identity verification (13.5.1)
- Applicant opts in, chooses one government-issued document (JPG, PNG, PDF, max 3 MiB), submits a private request. Consent is recorded. Email confirmation alone is not identity verification.
- Authorized admin/moderator checks the document, name, authenticity indicators and ownership evidence; if uncertain, request additional confirmation or reject. The system is manual review, not government database validation, liveness/biometric KYC or proof of qualifications/employment. Never approve a reviewer’s own request.
- Badge expires after one year and is permanently revoked on professional-name change; applicant can remove it. Reviewer can revoke it.
- Private storage is owner-only at the authenticated Storage API; authorized reviewers can download during review only through the audited server route. The service-signed download is short-lived. Approval requires an evidence-access audit event and explicit reviewer confirmation. No public documents. Reviewers must avoid keeping local copies and delete any downloaded evidence after reviewing. Evidence is untrusted; use a safe viewer.
- Applicant can remove evidence after a decision or withdraw, and can manage previous evidence. Existing authenticated daily post-bin cron also removes identity files via Storage API after 30 days from decision and expires incomplete requests after 30 days. A bounded batch is processed before post-media cleanup and retried on subsequent daily runs; monitor identityCleanupFailed.
- Review queue: /admin/verification. Applicant: /settings/verification (Android: Settings → Identity verification).
- Before launch: assign and train actual reviewers, verify the review procedure and privacy notice/retention policy, test a real upload/download with synthetic evidence and a physical device. No live identity evidence is used in automated tests.

## Operational activation
Intake fails closed until another email-confirmed authorized reviewer exists. The owner must explicitly designate a trained reviewer. A trusted operator may add the boolean `identity_reviewer: true` to that account's server-managed `auth.users.raw_app_meta_data` (preserve every other key); never use user-editable metadata and never grant general admin rights merely for identity review. Remove the boolean to revoke access. The reviewer signs in again and opens Settings → Review identity requests. A sole reviewer cannot submit their own request. No real reviewer has been designated by this implementation.
