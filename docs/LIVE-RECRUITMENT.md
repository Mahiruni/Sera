# Live recruitment and email delivery — 7 November 2026

## Scope
Public `/jobs` reads real Supabase records, with title/location/type search and paging. No sample jobs are inserted into the shared database. Numeric historical sample detail URLs remain demos; `/demo/jobs` provides the separate sample browser.

Verified accounts can publish self-reported jobs, close/reopen their own listings, save roles, apply once per job, withdraw, and exchange private in-app application messages. Employers review only applications to their own jobs and manually change stages. Candidate/employer preference never grants administrator or verified-employer status. There is no automated candidate ranking or selection.

Applications snapshot only the explicitly acknowledged name, skills, experience and cover note. Phone, email and other private profile fields are not shared. Candidate profile changes do not silently change existing applications. Withdrawn conversations are read-only. Lists currently show the most recent 100 applications/jobs and 200 conversation messages. External messaging, document upload, payments and employer verification are outside this release.

## Authorization evidence
`tests/recruitment.rls.sql` passes against the hosted project inside a rolled-back transaction with three disposable identities. It covers public discovery; own-job posting/status; private applications; candidate stage escalation denial; outsider read/write denial; immutable owner IDs; messages; closed-job rejection; withdrawal and outbox isolation. The welcome queue rejects duplicate active claims and never reclaims sent entries. Default broad table grants were explicitly revoked before applying selective table/column grants.

Daily limits: 10 job postings, 50 applications; hourly limit: 60 messages per account. Database triggers enforce these alongside verified-user RLS. Security-definer helpers are private, use an empty search path, and bind ownership checks to auth.uid(); trigger-only helpers have client execution revoked. No private profiles are exposed to job posters.

Current advisor has one existing Auth warning: leaked-password protection is disabled. No table/function security finding remains. No compliance certification or native-language review is claimed.

## Email status
Renderer supports English, Amharic, Afaan Oromo, Tigrinya, Arabic RTL and Somali. Afar and unsupported codes intentionally use English. Copy is initial product translation and still benefits from independent native-language review. Six-language Supabase templates and conditional subjects are generated by `scripts/build-email-templates.ts`; generated assets are not proof of hosted installation or inbox delivery.

Welcome delivery uses a private outbox row per verified user, a service-only claim function, a ten-minute lease, bounded attempts, retry backoff and stable message ID. Confirmation/callback and sign-in schedule delivery after responding. A protected daily Vercel cron retries the queue. Recipient comes from Auth admin lookup, never a caller-provided email. SMTP errors are recorded as a generic code, not raw credentials or message contents. SMTP acceptance followed by a lost database acknowledgement can still cause a retry/duplicate; this is not an exactly-once delivery guarantee.

The existing server-only Supabase service key is configured in production. CRON_SECRET was generated and saved directly as a production secret. **SERA_SMTP_PASSWORD must be entered securely in Vercel before automatic welcome delivery can activate.** It is the password for the existing mahir@hisabtech.com mailbox at smtp.hostinger.com:465. The password stored in Supabase Auth was not read or copied. Never commit the password. Missing configuration defers welcome sends without breaking sign-in or confirmation. A deployment is needed after adding the new environment variable.

Production activation should verify the conditional Auth templates, a fresh localized confirmation/recovery, one welcome inbox receipt, and a second dispatch that sends nothing for the same user. The code and RLS checks do not replace those delivery checks.
